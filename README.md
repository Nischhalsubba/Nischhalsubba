## Design Practice

I design products where the interface has to carry **real operational complexity**: roles, permissions, dense information, high-trust actions, system states, reusable patterns, and edge cases that cannot be solved by polishing one ideal screen.

My work spans **product strategy, UX research, information architecture, interaction design, accessible UI, prototyping, design systems, and implementation-aware delivery**. I stay close to engineering because good design decisions should survive the handoff.

| **Clarity** | **Systems** | **Delivery** |
|---|---|---|
| Find the actual user decision before visual polish hides the problem. | Reuse rules, states, and interaction logic—not only components. | Document behavior, responsive rules, accessibility, and implementation intent. |

<div align="center">

**Design principle:** *Make complexity easier to reason about.*
